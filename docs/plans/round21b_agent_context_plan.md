## Contracts

### The file
- Path: `~/Library/Application Support/Ezra/Context/context.md`. UTF-8 text, the user's words as typed (line breaks `\n`; a `\r\n` file is read with its `\r` dropped and written back with `\n`). Nothing else in the file: no front matter, no heading, no date.
- Read: missing or empty → empty context. Not decodable as UTF-8 → empty context, and before the first write the unreadable file is moved to `context.unreadable.md` (the memories pattern), so nothing a person put there is overwritten; the tab says "the context file couldn't be read; it was kept as context.unreadable.md". Over 2,000 characters (hand-edited) → the whole text is shown in the editor with the counter red ("2480 / 2000 · only the first 2000 reach ezra"); the prompt gets the first 2,000 characters; the editor refuses more typing until it is under the limit; a save writes what the editor holds (the user's text is never silently cut on disk).
- Write: atomic (`write(to:atomically:)` or a temporary file and replace), the folder created if missing, off the main thread. A failed write is reported, not thrown away: the editor keeps the text and the mark says "couldn't save: <short reason>" in red; the next keystroke tries again.
- Self test: `EZRA_CONTEXT_DIRECTORY` is honoured only with `EZRA_PANEL_SELF_TEST=1`; a self test with no variable gets `ezra-panel-self-test-context-<suffix>` in the temporary directory; an ordinary run always uses the real folder. `EzraPanelDataLocations` gains `contextDirectoryURL: URL? = nil` (last parameter, so every older caller compiles and gets nil), filled by `real` and `forRun`, counted by `touchesARealFolder`.

### What the model gets (`EzraAgentContextText`, pure)
- `hiddenLineNumbers(in:) -> [Int]`: 1-based numbers of the lines (split on `\n`) where `EzraSecretDetector.textHoldsCredentialShape` is true. Computed on the full text as the editor shows it, so the numbers match what the user sees.
- `textForPrompt(from:) -> String`: the lines that are not hidden, joined with `\n`, trimmed of leading and trailing blank lines, then cut to 2,000 characters (hide first, then cut, so the numbers above and the cut agree with the editor).
- `blockText(forUserText:) -> String?`: the heading plus `textForPrompt`, or nil when `textForPrompt` is blank (so a context of only hidden lines, or only whitespace, sends today's two blocks).
- `characterCount(of:)`: `String.count` of the text as shown. Two numbers exist and the brief uses them apart: the **tab's counter** is this raw count of the editor's text (2480 when a hand-edited file is over the limit, hidden lines included); the **metrics field and the driver's `contextCharacterCount`** are the characters that actually reached the block, after hide-and-cut (`textForPrompt(from:).count`).

### The store (`EzraCore/EzraAgentContextStore.swift`, Foundation only, `final class`, `Sendable` with a lock)
- `init(directoryURL:)`, `static var defaultDirectoryURL`, `static func directoryURLForRun(environment:temporaryDirectoryURL:uniqueFolderNameForSelfTest:)` (copy of the memories rule), `fileURL`.
- `currentText: String` — **the in-memory copy, which is what a turn reads**. Set by `reloadFromDisk()` (at launch, off the main thread; and when the tab opens, only if no save is pending, so a hand edit made on disk shows the next time the tab opens or at the next launch) and by `setCurrentText(_:)` (every change of the editor and "clear"). This is a deliberate difference from reading the disk at every turn: a turn that starts within the autosave delay would otherwise read a file that lacks the last second of typing, and no disk read is on the turn path at all.
- `promptBlockText: String?`, `promptCharacterCount`, `hiddenLineNumbers` (from `currentText`).
- `scheduleSave()` (0.8 s after the newest call, on the store's own serial queue; one write per burst), `flushPendingSaveNow()` (synchronous, used at panel close and at quit; a 2 KB file), `saveNow()` (for "clear"). `saveStateChangedHandler: ((EzraAgentContextSaveState) -> Void)?` called on the main queue with `.saving`, `.saved(at:)` or `.failed(reason:)`.
- `reloadFromDisk() -> EzraAgentContextLoadResult` (`.loaded`, `.empty`, `.unreadableFileMovedAside`, `.failed(reason:)`). Nothing in the store prints text; the console gets only "context: 96 characters, 0 lines hidden".

## Known limits
- A hand edit of the file while the app runs shows at the next tab open or the next launch, and a hand edit made while the tab is open with a save pending is overwritten by that save.
- A turn that starts while the user is mid-sentence in the editor sends the half-typed context (the in-memory copy is read at assembly).
- The fixed confirmations and quick commands (round 19) do not read the context (they have no prompt): "always say sir" written in the context changes spoken replies, not "opened safari."; the persona's "call me" is the way to do that.
- Shape rules only: a password written as a plain word ("my wifi password is hunter2") reaches the model, as it would in a hand-edited note; the base prompt's rule about never saying a saved secret aloud applies to notes, not to the context.
- Square brackets in the context are kept as written (the block is never parsed as a reply); the model could echo a tag-like string from it, and the reply's own tag parsing then decides.
- The context is one block for every chat; an instruction in it that fits one project and not another is the user's to manage.
- The heading tells the model it cannot change the context; this is a prompt rule, and the code guarantee is only that no write path exists.
- The counter counts characters, not tokens; a context of 2,000 CJK characters is more than 500 tokens.
- The context's cache is written again after every edit and after five quiet minutes, like the base prompt's; a user who edits between every turn pays the write each time (about $0.0017).
- Nothing in this round is verified in the running app by the builder.
