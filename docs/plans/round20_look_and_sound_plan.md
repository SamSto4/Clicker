## The Worker contract (both sides build to this; the Worker is the orchestrator's PR)

Everything below the app sends and expects. The orchestrator writes the Worker to it and deploys with Sam; the builder writes the app to it and checks the request bodies offline.

### `POST /voices`
- Request: the app token header; an empty body or `{}`.
- Worker: `GET https://api.elevenlabs.io/v1/voices` with `xi-api-key` (**verify before building**: from memory the response is `{"voices": [{"voice_id", "name", "category", "labels": {...}, "preview_url", ...}]}` and lists the account's "my voices", premade ones included; there is also a paginated `GET /v2/voices` with `page_size` and `next_page_token`; if v1 is deprecated or capped, the Worker pages through v2 and returns the same shape below). Cached in the isolate for 10 minutes (a module-level variable with a timestamp; an isolate restart simply refetches).
- Response `200 application/json`:
  ```json
  {
    "voices": [
      { "id": "<voice_id>", "name": "Rachel", "category": "premade", "labels": { "accent": "american", "gender": "female", "age": "young", "description": "calm", "use_case": "narration" } }
    ],
    "defaultVoiceId": "<the value of ELEVENLABS_VOICE_ID>"
  }
  ```
  Only `id`, `name`, `category` (ElevenLabs' word: `premade`, `cloned`, `generated`, `professional`, or another string), `labels` (string values only; absent or non-string values dropped), `defaultVoiceId`, and one optional boolean `speedSupported` (absent or `true` means the `speed` field works on the model the app sends; the Worker sets `false` only if the verification below finds that `eleven_flash_v2_5` has no `speed`, and the app then hides the speed row and sends no `speed`). **Never the key, never `preview_url` unless Sam picks option (a), never `settings`, never `samples`.** Names and labels are the account's own text and are cut to 60 characters each. `defaultVoiceId` is included even when that voice is not in the list (then the app shows a "default (worker)" row).
- Errors: an upstream failure passes the status through with a JSON body like the other routes; a missing `ELEVENLABS_API_KEY` is a 500. The app treats any non-200 as "couldn't load the voices" and keeps what it has.

### `POST /tts` (extended; today's body still valid)
- Request body: today's three fields plus two optional ones:
  ```json
  { "text": "...", "model_id": "eleven_flash_v2_5",
    "voice_settings": { "stability": 0.5, "similarity_boost": 0.75, "speed": 1.1 },
    "voice_id": "<voice_id>" }
  ```
  `voice_id` is absent when nothing is chosen; `speed` is absent at the default (100%). **With nothing chosen the body is byte-identical to today's** (a smoke check keeps today's body as the reference).
- Worker: parses the JSON (a body that is not a JSON object is a 400 `{"error": {"type": "bad_request", "message": "body must be a json object"}}`); takes `voice_id` out of the body (**verify before building**: the voice goes in the URL path, and from memory ElevenLabs validates the body strictly, so an unknown field may be a 422; removing it is right either way); if `voice_id` is a string that is in the cached account list, uses it in the path, else uses `ELEVENLABS_VOICE_ID` and adds the response header `X-Clicky-Voice-Fallback: 1` (so the app can say so, see stage 3); if `voice_settings.speed` is present it is clamped to the ElevenLabs range (**verify before building**: from memory `voice_settings.speed` exists on the current models including `eleven_flash_v2_5`, range 0.7 to 1.2, default 1.0; if the real range differs, the Worker clamps to the real one and the app's five steps below stay inside it); forwards the rest unchanged; streams the audio back as today. Round 19's cap counting, if it exists, counts `text.length` as before.
- The app also clamps `speed` to 0.7...1.2 (`EzraVoiceSettings`) so a wrong stored value can never leave the app.

### What stays
- `POST /chat` and `POST /transcribe-token` are untouched. No new secret. `ELEVENLABS_VOICE_ID` stays the default and the fallback.
- The orchestrator tests the Worker with `wrangler dev` (`/voices` lists and never includes the key; `/tts` with an unknown id falls back and sets the header; with a listed id the voice changes; with `speed` the pace changes; today's body still works), then deploys. ### Stage 1: the cursor style (pure)
- **`EzraCursorStyle`** (`EzraCore/EzraCursorStyle.swift`, `Codable`, `Equatable`, `Sendable`): `colourHex: String` ("#RRGGBB", upper case), `shape: EzraCursorShape`, `size: EzraCursorSize`, `glow: EzraCursorGlow`. **`EzraCursorStyle.default` is today's look exactly**: `#3380FF`, `.triangle`, `.medium`, `.soft`. A check asserts the numbers the overlay derives from the default: a 16-point frame, a rest angle of -35°, a glow radius of 8 at rest and 8 + (scale − 1) × 20 in flight with the colour at full opacity, bubble shadows at opacity 0.5 and radius 6, waveform and spinner shadows at opacity 0.6 and radius 6.
- **Shapes** `EzraCursorShape: String, CaseIterable` = `triangle`, `arrow`, `chevron`, `dot`, `ring`. Each has `title` (the word), `pointsTowardFlight: Bool` (true for triangle, arrow, chevron; false for dot, ring), `restAngleDegrees` (-35 for the pointed ones, 0 for the round ones), `isStroked: Bool` (true for ring and chevron; the overlay strokes those and fills the others), and `strokeWidthShare` (ring 0.16, chevron 0.22 of the frame). **Every pointed shape is drawn with its tip pointing up at 0°**, so the flight rotation at `OverlayWindow.swift:626` (`atan2 + 90`) is untouched and round shapes simply apply 0.
- **Geometry** `EzraCursorShapeGeometry.outline(for:in: CGRect) -> EzraCursorOutline` (pure; `CGPoint`/`CGRect` are allowed in EzraCore, precedent `EzraSceneModel.swift`): a list of path parts (`move`, `line`, `arc(center, radius, startDegrees, endDegrees)`, `close`) the app turns into a SwiftUI `Path`. Triangle: today's three points (`OverlayWindow.swift:60–67`, kept to the digit). Arrow: the classic pointer, seven points: tip at top centre, two barbs at 0.42 of the height out to the full width, a tail 0.3 wide down to the bottom, mirrored. Chevron: an open "V" with the point at top centre and the two legs ending at the lower corners, stroked with round caps and joins (no fill). Dot: a circle of 0.78 of the frame, centred. Ring: a circle of 0.86 of the frame, stroked. A check: every point of every shape lies inside the rect with 0.5 point of tolerance (stroke width excluded), and the triangle's points equal `Triangle.path(in:)`'s points.
- **Sizes** `EzraCursorSize` = `small` (0.75), `medium` (1), `large` (1.4): `frameSideInPoints` = 16 × scale (12, 16, 22.4). The waveform and spinner scale by the same factor (`scaleEffect`, so their internal numbers stay).
- **Glow** `EzraCursorGlow` = `off`, `soft`, `strong`: `cursorGlowRadiusAtRest` 0 / 8 / 14, `cursorGlowRadiusGainPerFlightScale` 0 / 20 / 30, `cursorGlowOpacity` 0 / 1 / 1 (and a second, wider shadow at 0.35 opacity and 2× radius for `strong`), `feedbackGlowRadius` (waveform and spinner) 0 / 6 / 10 with opacity 0 / 0.6 / 0.8. ## Known limits of this round, stated up front
- The voice list is the account's "my voices"; adding a voice from ElevenLabs' library is done on their site, then "refresh" in the tab. Cloning or uploading a voice is out of scope.
- One voice for everything: the persona (round 18) does not get a voice of its own; a later round could tie a voice to a persona.
- The pill's colour changes at its next appearance, not while it is on screen (its layers are built per show).
- A near-black or near-white custom colour can be hard to see on some screens; the preview's two halves are the warning, nothing refuses it.
- The sample is cached per voice and speed, so the first play of each pair needs the network; the default row's sample is keyed on the list's `defaultVoiceId`, so after a change of the Worker's default it is right once the list has been refreshed, and before that refresh the row plays the old default's cached sample once.
- The glow is a SwiftUI shadow in a full-screen overlay window, so a strong glow at a screen edge is simply cut by the edge.
- The `speed` field's name and range, the `/v1/voices` shape and the strict-body behaviour are from memory and marked for verification; the contract's optional `speedSupported` field is the one switch for a negative finding, so the app needs no change either way.
- Nothing in this round is verified in the running app by the builder; the orchestrator builds, runs the two self tests and tests the Worker in `wrangler dev`; Sam's hand tests cover the rest.
